# 角色编辑

实现采用 `CharacterDocument`、`CharacterEditSession`、`CardEditService`，与协议 v2 独立 Unity Player 配套使用。2026-11-09 已完成本机固定基线验收：81 张原始样本无损往返、1,467 条编辑路径、保存事务、实际界面、3 张编辑副本的游戏读取，以及 84/84 张卡的静态、动态画面对照和视觉复核均通过。构建与证据位置见 [验收结果](UNITY-VALIDATION-RESULTS.md)。

## 操作

人物详情、右键菜单和预览工具栏均有“编辑角色”。双击保持打开预览。左侧选择分类与分组，中央调整镜头、播放状态和环境，右侧修改参数。素材窗口支持名称搜索、原版/MOD 筛选、缩略图及定位当前选项。缺失资源保留引用并显示原因。

Ctrl+Z/Ctrl+Y 撤销、重做；一次滑条拖动合并成一次操作。参数旁的恢复按钮、分类恢复和全部恢复均返回最近保存状态。切卡、返回和关闭时可保存、放弃或取消。

Ctrl+S 与“另存新卡”默认保存为原目录的“原文件名-编辑.png”，重名自动编号。“更多”可选择其他目录或备份后覆盖。封面 PNG 从文件起点到 IEND 始终逐字节保留，因此封面不会随外观修改更新。另存继承标签、备注、收藏和分类；覆盖保留记录身份。

覆盖前验证完整源文件 SHA-256，备份位于 `Data/CardBackups/<记录ID>/<操作ID>.png`。同目录暂存、写回校验、原子替换及 `Data/Operations` 日志保证可检查和恢复。中断恢复仅补齐已提交文件的索引，不自动重新覆盖。保存失败保留草稿；“更多 → 恢复编辑备份”恢复完整原卡。

## 控件覆盖与数据规则

[字段清单](CHARACTER-EDITOR-FIELDS.csv)列出在本机 81 张样本卡上出现并完成往返测试的 1,467 条编辑路径、界面名称、范围、显示倍率及覆盖卡数。该数量不等于每张卡的可见控件数：性别、素材能力、发束数量、空配饰槽决定具体显示项。

| 分类 | 覆盖范围 | 联动/显示规则 |
| --- | --- | --- |
| 脸部 | 头型、脸型、下颌、脸颊、眼形、鼻、嘴、耳、皮肤纹理、眉、瞳孔、高光、睫毛、痣、胡须 | 男女资源类别；瞳孔同设；位置预设 |
| 身体 | 身形、胸部、腰臀、四肢、肤色、皮肤纹理、光泽、乳头等原版外观参数 | 男性隐藏女性专用项；滑条扩展范围 |
| 妆容 | 眼影、腮红、口红、彩绘及颜色、位置 | 彩绘和痣使用游戏布局顺序 |
| 发型 | 后、前、侧、附加发型；颜色、材质、发束、发饰、挑染 | 同设与自动配色；CmpHair 能力与发束节点 |
| 服装 | 上衣、下装、内衣、内裤、手套、连裤袜、袜子、鞋 | 材质、颜色、花纹、布局、破损、隐藏选项；CmpClothes 能力 |
| 配饰 | 原版 20 槽的类别、素材、挂点、两组变换、颜色、材质、服装联动与固定 | CmpAccessory 能力；扩展槽保留和显示，专属编辑不在范围内 |

字段依据本机 `ChaFileFace/Body/Hair/Clothes/Accessory` 与 `CharaCustom.CvsF/B/H/C/A` 数据、滑条扩展配置和素材组件核对。未编辑的超范围值不被夹紧。版本、未知字段、整数键、扩展标记、未知数据块和尾部内容保留原始编码；无修改输出与原文件完全相同。资源选择同步 Sideloader GUID、类别、Slot 和属性路径，切回原版移除该项旧引用。

预览以草稿快照更新，不重新读取原卡。修订号贯穿请求、完成回执和帧缓冲。形变、改色、配饰变换复用现有对象，更换素材重建相关部件；旧任务不会发布覆盖新草稿的画面。重连保留草稿、镜头、环境及播放状态。运行过程不加载游戏或插件程序集。

## 验证入口

`HS2Manager.Checks --card-edit --real-edit` 验证无损往返、字段读写、PNG/插件保留、撤销、文件冲突、占用、备份恢复和中断索引补齐。`--edit-preview --player <exe>` 验证画面变化、对象复用、原版/MOD 往返、修订取消及原卡隔离；`HS2Manager.UiChecks --character-editor --player <exe>` 验证实际界面流程。`--prepare-edit-game` 生成测试副本，测试采集器核对游戏实际读取值与资源选择。

画面对照固定本机资源/插件配置与卡片 SHA-256，四个静态视角、30Hz/360帧/24采样，人物和脸部区域 SSIM≥0.99、平均通道误差≤2/255，并要求局部视觉复核。测试额外固定动画材质时间、抗锯齿相位和抖动随机种子，保持已启用的游戏渲染效果。失败、缺失和未复核项目均不计通过。
