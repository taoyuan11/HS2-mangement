# 3D 预览进入角色编辑的生命周期检查（2026-11-12）

## 问题与修改

原流程先创建编辑器并显示编辑视图，再在 `NativeEditor::Initialize` 中重置旧预览。旧预览的同步析构会在 UI 线程等待渲染线程退出，此时 XAML 已开始切换视图，交换链仍可能关联旧面板。

`NativeWindow::OpenEditor` 现在保持忙碌状态，先取出旧预览并等待 `StopAsync` 完成，再创建编辑器。该操作先停止渲染，回到 UI 线程解绑交换链，再在后台释放渲染资源；等待期间 UI 消息循环继续运行。进入编辑器前重新检查窗口是否正在关闭。初始化失败时清理部分创建的预览和编辑视图，最后恢复忙碌状态并报告错误。预览人物列表的选择事件在忙碌时忽略，避免切换期间重新加载人物。

## 诊断范围

修改前的调试器对照测试在切换后关闭窗口时报告 `Free Heap block ... modified ... after it was freed`，检测堆损坏的调用栈位于 XAML 对象释放。它说明有释放后写入，不能单凭检测位置确定具体写入者。本机既有记录还包含 AMD 驱动异常，未将它们直接视为同一根因。

## 验证

- Release x64 构建、原生运行库审计通过，CTest 15 / 15 通过。
- 本次修改的两个 C++ 文件通过 clang-format 检查，`git diff --check` 通过。
- 独立 AddressSanitizer 渲染检查通过：暂停重绘、服装可见性、形体和颜色编辑、配饰替换、撤销重做、快速连续编辑以及工作线程释放均未报告内存错误。
- WinUI 的 AddressSanitizer 版本在进入测试场景前即于系统合成组件 `dwmcorei` 因 `0x8007000e` 失败，因此没有把它计为界面测试通过。
- 使用独立资料库、真实游戏资源和最大化窗口，验证预览加载期间进入编辑器、模型正常显示后关闭窗口，正常退出码为 0。
- 另一次独立启动中，确认 3D 预览已显示人物并持续渲染后点击编辑角色，随即按 Alt+F4；正常退出码为 0，没有新增原生异常日志。

验证结果覆盖本次测试场景，不能据此证明所有人物卡及显卡驱动组合均不会发生间歇性故障。
