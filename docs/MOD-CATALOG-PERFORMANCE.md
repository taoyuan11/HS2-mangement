# MOD 素材清单读取优化

2026-11-11，本机 Release 构建对比优化前后的 `CharacterCatalog::Load`。游戏资源位于 Z: 网络盘，测试缓存位于 C: 本地磁盘；使用独立测试数据目录，不修改游戏文件或用户资料库。

## 实测

同一份 MOD 索引选中 2,894 个 MOD，最终得到 14,067 条原版及 MOD 素材，前后均无警告。

| 场景 | 优化前 | 优化后 |
| --- | ---: | ---: |
| 无应用缓存时的 MOD 清单阶段 | 20.97 秒 | 2.68 秒 |
| 已有应用缓存时的 MOD 清单阶段 | 0.46 秒 | 0.24 秒 |
| 无应用缓存时的完整素材目录加载 | 21.22 秒 | 2.95 秒 |
| 已有应用缓存时的完整素材目录加载 | 0.50 秒 | 0.27 秒 |

首次 MOD 清单阶段耗时减少约 87%。计时不包含 MOD 索引扫描和类数据库构造；“无应用缓存”指独立数据目录中尚无清单缓存，未清空操作系统文件缓存。结果仅代表这批资源及本机条件，不作为测试中的硬性时限。

按分类、ID、GUID、来源、包路径及全部 CSV 字段排序后计算的 SHA-256 前后一致：

```text
D7A94C000310B358EAF8954CB75175DDCDD9F5CE517F40C5880AB7D13D1DB683
```

旧版 JSON 缓存迁移实测约 0.26 秒，结果摘要同样一致。

## 实现

- 利用现有 ZIP 条目索引跳过不含人物素材 CSV 的 MOD，继续保留这些 MOD 的资源包索引。
- 将每个 MOD 一个 JSON 文件改为每个游戏一个 MessagePack 清单缓存；按 MOD 路径、文件大小和修改时间单独校验。旧缓存可读取迁移。
- 最多四个工作线程读取未命中的 MOD，按原索引顺序合并，保留覆盖规则；进度回调留在调用线程，取消或异常时等待所有工作线程退出。
- 临时预览复用安装资源的持久清单缓存；包内资源使用会话缓存，安装资源与包内覆盖保持隔离。
- 缓存损坏时重新解析；缓存写入失败不丢弃已经读取成功的素材。

## 回归检查与复测

`character_catalog` 覆盖首次和重复读取、增删与修改 MOD、仅修改时间变化、来源元数据变化、缓存损坏、写入失败、无条目索引的兼容读取、资源包提供者、包内覆盖、取消后重试以及进度回调异常。`temporary_preview` 继续验证实际临时会话的作用域与清理。

```powershell
# 编译并执行 CTest 和 WinUI 构建
.\build-cpp.ps1 -Jobs 4

# 使用构建产物复测；data 必须是独立测试目录，首次运行会生成测试 MOD 索引
hs2_catalog_checks.exe --benchmark <game> <data> <classdata.tpk>
```

基准工具连续创建两个目录对象，分别报告首次读取及缓存读取的耗时、素材数量、警告数量与内容摘要。
