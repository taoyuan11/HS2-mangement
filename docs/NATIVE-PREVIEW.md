# 独立 3D 预览第一阶段

2026-11-07，1.1.0-preview.1。

## 已实现

人物卡的 Custom 块包含三段带长度的 MessagePack 数据。程序以受限的数据解析器读取基础头部、四种发型编号与肤色/发色，不反射加载游戏程序集，不执行卡片中的插件数据。

AssetsTools.NET 3.0.5 读取 Unity 2018 资源包的内嵌类型树、二进制人物资源清单、Prefab 层级、静态变换与可见渲染器。网格解码覆盖分离顶点流、Float32/Float16 坐标、16/32 位索引、子网格 baseVertex、法线和 UV；反转坐标系及三角形顺序后供 WPF 使用。头部和发型附加到基础身体的 `cf_J_Head` 连接点。

桌面端直接使用冻结的 `MeshGeometry3D` 与基础材质。几何转换在后台完成，视口交互在 WPF 内进行。没有 GPU 到 CPU 的逐帧读回、IPC 图片流或后台游戏进程。截图仅在用户请求时渲染 1280×720 图片，保持原视口的垂直取景。

索引和未着色的 Prefab 网格以 Brotli 缓存在 `Data/NativePreview/native-v1`，键包含源文件完整路径、长度和 UTC 修改时间。缓存读取后验证几何数据；损坏数据重新解析。每次预览重新读取人物卡颜色与部件选择，不把另一张卡的颜色复用到当前卡。缓存仍依赖源目录在线；没有承诺离线资源镜像。

默认解决方案、桌面端与发布脚本不再引用/编译/安装旧桥接插件。旧桥接源码和显式 `--preview` 测试入口仅为历史保留，不参与独立预览，也不会自动回退启动游戏。独立检查入口为 `--native-preview`。

## 第一阶段限制

- 基础身体、头部和发型的静态 T 姿态；未应用捏脸、体型、骨骼形变、表情、动画或物理。
- 纯色漫反射与简化高光；不还原皮肤贴图、眼睛贴图、透明发片、遮罩、游戏 Shader 或画质插件。
- 服装、配饰与 MOD 部件不加载。已识别的 MOD 头部/发型不会按数值 ID 错配为基础资源；无可用头部时也跳过发型。
- 资源包需 Unity 2018 内嵌类型树。压缩顶点、外置顶点流、跨包 Mesh 引用和非三角形拓扑暂不支持，逐部件提示原因。
- 不保证人物卡视觉相似；同一基础网格的不同捏脸参数在当前阶段不会体现。界面常驻限制说明。

## 验证

本机游戏 `HS two DX - TSYMQ`，Unity 2018.4.11f1，Windows x64，.NET SDK 10.0.403。测试使用真实男女样本的副本，原卡 SHA-256 未变。

- 男性：53,642 个三角形；首次资源读取约 1.02 秒，缓存读取约 0.10 秒。
- 女性：52,208 个三角形；首次资源读取约 0.75 秒，缓存读取约 0.08 秒。
- 上述为本机当前资源状态下的样本测量，包含资源解析/缓存读取，不包含 WPF 几何构建、首次 .NET 启动，也不是清空操作系统磁盘缓存的基准。尚未覆盖全部卡片。
- 原生资源测试覆盖男女基础网格、索引范围与有限坐标、头部连接、缓存一致性/损坏恢复、取消、MOD 省略提示、未加载 Unity/BepInEx 程序集及无新增游戏进程。
- WPF 检查覆盖真实视口、正侧镜头差异、缩放/平移、背景灯光、1280×720 截图、连续选择以最新为准、关闭时取消与清空模型。对实际渲染图进行了人工视觉检查。
- 核心管理 30 项回归检查通过。布局检查覆盖浅色/深色/系统 × 100%/150%/200% × 资源库/预览。
- 窗口关闭回归覆盖资源库/预览 × 空闲/后台任务未结束四种情况，通过原生标题栏关闭消息验证单次关闭、连续点击、取消与窗口句柄释放。修复前可复现 `Closing` 中重复 `Close()` 的异常；修复后先完成清理，再由 UI 调度器关闭窗口。此检查随默认 UI 检查运行，也可使用 `--window-close` 单独执行。

```powershell
.\build.ps1 -GamePath 'Z:\games\hs2\HS two DX - TSYMQ' -PreviewTest
```

## 后续阶段

1. 衣服和配饰：解析 Coordinate、部件绑定与身体遮罩，明确哪些服装组合可准确显示。
2. 材质：读取基础贴图、透明发片与 UV 参数，逐种替代游戏 Shader。
3. 人物形变：解析 shape animation、骨骼映射与捏脸/体型参数，验证不同卡片的实际几何差异。
4. MOD：按 GUID 与 Slot 解析 Sideloader 清单和资源，按类型扩展支持，保留不支持项诊断。

不把复制 `UnityEngine.dll` / `Assembly-CSharp.dll` 当作渲染方案：这些程序集依赖 Unity 原生运行时及游戏初始化。独立方案读取序列化资源并在自己的视口渲染，不能继承游戏运行时的全部行为。
