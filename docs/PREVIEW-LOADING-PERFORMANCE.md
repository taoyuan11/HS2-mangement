# 3D 预览资源与角色组装优化

2026-11-11，使用本机 Release 构建、Z: 网络盘上的同一游戏资源和本地测试缓存，对比本轮修改前后的完整角色预览链路。

## 实测

已有应用缓存时，每张人物卡前后各运行三次，交替运行两个版本，取中位数：

| 样本 | 准备角色：优化前 → 优化后 | 首帧：优化前 → 优化后 | 首帧耗时减少 |
| --- | ---: | ---: | ---: |
| 女性 navi | 2.95 → 2.55 秒 | 4.63 → 4.02 秒 | 13.3% |
| 男性 HS2_ill_M_000 | 2.02 → 1.89 秒 | 3.36 → 3.01 秒 | 10.5% |

最终版本另用两个独立空预览缓存目录测试女性人物卡首次加载，准备阶段为 18.59 → 17.42 秒，首帧为 21.22 → 19.69 秒。目录仅预置同一 MOD 索引，不包含素材清单、身体清单、着色器清单、解包或解压块缓存。该组只有一次前后测量，网络盘波动明显，不能视为稳定的首次加载提升比例。

没有清空操作系统文件缓存。首帧计时包含角色服务构造、准备、运行时、渲染管线及首次 GPU 读回，不包含 WinUI 启动和 MOD 索引扫描。数据仅代表这两张人物卡及本机条件，不作为自动化测试的时限。

两张人物卡每次都执行八帧渲染，并验证尺寸调整和交互历史重置；保存的第 1、8 帧 PNG 的 SHA-256 在优化前后完全一致。首次读取生成的身体与迁移清单文件逐字节一致，包含 147 条身体部件记录。

## 改动

- 依赖包身份索引只读取 UnityFS 目录，不为查询 CAB 名称完整解压、解析未使用的包，也不占用读取器缓存预算。保留重复身份检测、顺序、增量添加及失败重试行为。
- 资源导出名称按类别建立索引，复用完整路径、文件名与去扩展名别名。保留导出优先于对象名、重复导出顺序和贴图尺寸筛选。
- Unity 类型树预先计算子树边界及直接子字段数量，解析大数组时复用布局并一次分配字段空间，减少重复扫描和内存分配。
- 组件转换只复制当前字段，避免逐层深拷贝整棵子树；骨骼修改与头部骨架对齐按名称索引，保留同名骨骼的首项语义及修改顺序。
- 同次准备中的插件 DLL、内嵌着色器包复用读取与校验结果；缓存随该次准备结束释放。
- 首次身体清单最多四路并行读取，仍在调用线程按原索引顺序应用覆盖和迁移；取消或异常会等待工作线程结束。

## 验证与复测

`hs2_asset_loading_checks` 覆盖嵌套和空数组、截断及不匹配类型树、资源别名优先级、类别和尺寸筛选、组件字段保真、延迟解压、CAB 歧义、失败重试与取消。`cpp_extensions` 增加跨批次身体清单覆盖、迁移、缓存一致性、取消和损坏归档恢复检查。

```powershell
# 编译原生模块、运行 CTest、构建 WinUI 并审核运行库
.\build-cpp.ps1 -Jobs 4

# 使用独立的测试数据和输出目录
hs2_render_frame_checks.exe <game> <data> <classdata.tpk> <card.png> <output> <physics-directory>
```

`loading-performance.json` 现在还输出每个准备阶段的耗时，以及独立的 CAB 目录索引次数和耗时，便于区分配置读取、模型准备、骨骼网格组装与后续渲染开销。
