### 第二轮实现

- 组件引用网格、材质、贴图和文本资源时，直接查询名称，避免仅为名称解析整棵网格形变或贴图参数树。Transform、脚本组件和 GameObject 的引用仍保留原有转换规则。
- 网格转换使用临时参数树，成功生成的网格继续由当前人物资源存储缓存。此前通过 `Metadata` 借出的对象不删除、不修改，保持引用有效；减少中间数据长期占用读取器预算和随后的重新读取。
- 着色器扫描最多四路构造独立读取器，原有读取器直接复用；按路径顺序在调用线程解析名称、设置脚本回调并提交缓存。名称索引保留原大小写及导出别名，淘汰读取器后仍可查询，增量扫描和失败重试不重复提交。取消或异常会等待本批工作全部结束。
- 身体选择和着色器清单复用人物素材目录已选择的 MOD 快照，省去两次完整索引读取和反序列化；空快照仍是有效选择，临时预览的覆盖顺序保持不变。插件存在性及配置文件仍在每次准备时读取。

读取器预算仍为 512 MiB / 64 个。并行批次及调用方持有的读取器可能暂时超过预算，已处理批次对象立即释放；本轮不新增跨人物共享的可变场景缓存。

## 改动

- 依赖包身份索引只读取 UnityFS 目录，不为查询 CAB 名称完整解压、解析未使用的包，也不占用读取器缓存预算。保留重复身份检测、顺序、增量添加及失败重试行为。
- 资源导出名称按类别建立索引，复用完整路径、文件名与去扩展名别名。保留导出优先于对象名、重复导出顺序和贴图尺寸筛选。
- Unity 类型树预先计算子树边界及直接子字段数量，解析大数组时复用布局并一次分配字段空间，减少重复扫描和内存分配。
- 组件转换只复制当前字段，避免逐层深拷贝整棵子树；骨骼修改与头部骨架对齐按名称索引，保留同名骨骼的首项语义及修改顺序。
- 同次准备中的插件 DLL、内嵌着色器包复用读取与校验结果；缓存随该次准备结束释放。
- 首次身体清单最多四路并行读取，仍在调用线程按原索引顺序应用覆盖和迁移；取消或异常会等待工作线程结束。
