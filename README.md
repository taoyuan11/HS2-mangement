# HS2 Manager

中文 Windows 11 人物卡管理器。纯 C++20 / C++/WinRT / WinUI 3，便携部署。人物管理、编辑、Direct3D 11 预览和模型导出均由 C++ 实现，不加载 CLR、.NET 业务程序集或 Unity 引擎，不执行游戏及插件 DLL。模块与数据兼容规则见 [C++ 迁移说明](docs/CPP-MIGRATION.md)。

## 开始使用

1. 将 `HS2Manager-1.5.0-cpp-win-x64.zip` 解压到本机磁盘，例如 `D:\Apps\HS2Manager`。请完整解压，保持程序与其他文件相对位置。
2. 双击 `HS2Manager.exe`。已包含 WinUI 与 VC++ 运行库，无需安装 .NET。
3. 首次启动自动检测 HS2 游戏目录，支持程序附近、系统登记的安装位置和各盘常见游戏目录（包括映射网络盘），找到后保存路径再扫描。未找到时提示手动选择包含 `HoneySelect2.exe`、`HoneySelect2_Data` 和 `abdata` 的游戏根目录；选择“稍后设置”可先进入资料库，之后在左下角“设置与连接”配置。后续启动优先使用已保存的有效目录，目录失效时重新检测。自动检测限于常见位置和浅层目录，深层、自定义或未映射的网络位置可手动选择；也可添加其他人物卡目录。
4. 首次启动默认仅扫描女性人物卡目录 `UserData\chara\female` 的当前层，建立本地封面和元数据索引，再读取 MOD 清单。在“设置与连接”可开启“递归检索人物卡（包含子目录）”，该开关默认关闭，同时适用于默认目录和额外人物卡目录。关闭递归后，已索引的子目录内容仍会保留。NAS 首次扫描需要一些时间；底部显示进度并提供取消。

本机磁盘运行时，`Data` 在程序旁边，保存 `library.db`、`settings.json`、`Covers`、`CardBackups`、`Operations` 和 `Logs`。便携包位于 NAS 时，自动将原有资料复制到 `%LOCALAPPDATA%\HS2Manager\Portable\<安装路径标识>\Data`，保留原件；之后使用本机资料库。数据库、封面与缓存均留在本机，游戏与人物卡可以位于 NAS。实际数据位置可在“设置与连接 → 数据与维护”查看，也可用 `--data "D:\HS2ManagerData"` 指定本机目录。NAS 上的程序文件和本机资料库需要分别备份；更换电脑不会自动同步收藏与备注。

关闭窗口、Alt+F4 和任务栏关闭会先取消当前任务、等待渲染线程结束、解除交换链并关闭资料库，再结束进程。确认退出后的清理最长等待 30 秒；超时会记录到 `native-error.log` 并结束当前进程，已提交数据及操作恢复日志保留，未完成任务交由下次启动恢复。保存／放弃／取消对话框等待用户选择期间不计时，取消关闭会撤销期限。原生或 XAML 致命异常记录后直接结束；程序启动时禁用本进程的 WER 崩溃／无响应快照，避免产生继续映射 DLL 和数据库的克隆。模型转换子进程由 Windows 作业管理，主程序被任务管理器强制结束时也随之回收。正常清理完成后不再运行第三方 DLL 的进程卸载回调，避免显卡或 COM 的卸载死锁。

旧版本异常退出后，Windows 错误报告快照可能继续占用 SQLite 的共享内存文件，导致下次启动出现 `SQLite (1546, Win32 1224)`。程序会保留原始数据到同级 `Data.startup-backup-<标识>`，从 DB 和 WAL 建立通过完整性检查的备份，再使用独占 WAL 索引恢复启动，保留已提交的收藏、标签和备注。恢复记录及启动错误见实际数据目录中的 `native-error.log`。

## 程序更新

在“设置与连接 → 程序更新”查看版本、更新说明和下载进度。默认启动后每天检查一次正式版，可关闭自动检查；发现新版本后由你点击下载，校验完成后确认“重启并安装”。更新保留资料库、恢复备份和用户文件；安装前请关闭同一安装的其他实例及 MCP 连接。旧版用户需先手动安装一次 1.5.0 或更新的便携包。

在 `main` 分支运行 `./push-releases.cmd 1.5.1`，自动更新 `VERSION`、提交全部未忽略改动，并推送代码和版本标签，在 GitHub 云端构建、测试及发布 Release。版本号为必填参数，也接受 `v1.5.1`。使用方法、发布附件和失败恢复见 [发布与程序更新](docs/UPDATES.md)。

## 浏览与整理

主界面的“角色工程”“mod工程”分别显示对应类型的工程列表，可新建、继续编辑、恢复快照、复制和重命名工程。工作台支持网格、UV、雕刻、贴图、蒙皮、多素材构建、成品导出和可回退安装。操作与工程恢复说明见 [创作工作台](docs/CREATION-WORKBENCH.md)。

- 左侧分为全部人物卡、收藏、完全重复文件、需要关注、可恢复隔离区，以及虚拟分类和真实文件夹。
- 搜索名称、文件名、标签和备注；支持性别、标签筛选及名称、修改时间、大小排序。
- 单击显示详情；双击有效人物卡打开 3D。点击列表上方“多选”显示勾选框，单击勾选或取消，可“全选当前结果”“清空”；也保留 Ctrl / Shift 多选。多选模式下双击不会打开预览，右键未选中的卡片会加入选择。底部操作栏或右键菜单可批量收藏、添加标签、分类、导出、移动和隔离。
- 切换多选模式保留选择，搜索、筛选和切换分类会清空选择；“全选当前结果”仅选择当前可见结果，包含滚动区域外的卡片。
- 标签、收藏、备注、虚拟分类保存在数据库中。编辑标签或备注后点击“保存标签与备注”或按 Ctrl+S。
- 重复检查读取完整文件并计算 SHA-256，包括 PNG 尾部人物数据。同一封面不一定是同一人物卡。
- 普通 PNG、服装卡和解析异常项显示在“需要关注”，不会冒充人物卡加载。
- 新增或外部修改文件后点击“刷新”或 Ctrl+R。此版使用手动增量刷新，不持续监视网络目录。

## 导入、导出与恢复

拖入 PNG / 文件夹，或点击“导入人物卡”。导入默认复制，按性别放入游戏 `male` / `female` 目录；同名自动保留两份。导入与导出都会逐字节保留人物数据，并校验 SHA-256。

选好人物卡后点击“导出”，选择导出级别和目录组织方式，再选择**游戏目录之外**的输出位置。

| 导出级别 | 包含内容 |
| --- | --- |
| **一级：仅原始 PNG** | 完整原始人物卡，保留嵌入的人物及扩展数据；不扫描外部依赖，游戏资源离线时仍可导出能读取的有效卡片 |
| **二级：包含 MOD** | 一级内容＋关联 MOD，包括迁移映射包和可确认的资源提供包 |
| **三级：包含插件** | 二级内容＋依赖插件及递归依赖 DLL |
| **四级：包含配套资源** | 三级内容＋可识别的外部贴图、独立资源文件和插件配套文件，与此前完整资源导出范围相同 |

首次默认第二级，确认输出位置并开始导出后记住所选级别，重启后保留。取消导出窗口或位置选择不会改变记忆。所有级别均可选择以下目录方式，目录方式每次默认按角色分文件夹：

- **按角色卡名称多文件夹**（默认）：每张卡按卡内人物姓名建立独立文件夹，原始 PNG 位于 `UserData/chara/female` 或 `male`，同时包含所选级别的关联文件。
- **合并导出**：全部卡片和所选资源放入 `角色卡合并导出` 文件夹，共享 MOD、插件和资源只复制一次。

例如，第二级独立导出为 `人物姓名/UserData/chara/female/原文件名.png` 和 `人物姓名/mods/…`；合并导出为 `角色卡合并导出/UserData/chara/…` 和 `角色卡合并导出/mods/…`。将角色文件夹或合并文件夹**里面的游戏目录**复制到 HS2 根目录。一级需要目标游戏已有 MOD、插件及配套资源；二级需要已有插件及配套资源；三级需要已有外部贴图、独立资源及插件配套非 DLL 文件。第四级的目标游戏需已安装 BepInEx，插件沿用目标游戏设置。所有级别均不包含插件配置、基础加载器或整套游戏。未知扩展及使用绝对路径的资源可能仍需在目标游戏中调整。

导出会重新读取卡片，二至四级会更新依赖索引，按级别收集有效版本的 MOD、迁移映射包、可确认的 Shader/外部资源及递归插件依赖。同名人物文件夹、已有导出目录和同名卡片文件均自动加序号；固定资源路径出现不同内容时跳过冲突，不覆盖。原始 PNG 和游戏目录保持不变。

资源检查以卡片实际引用的类别和编号为准，支持 Sideloader 用 PNG 提供逻辑 `.unity3d` 路径中的贴图。未使用的 MOD 清单行不算作该卡的缺失依赖；已确认全部关闭的 BoobSettings 参数和仅有版本信息的 PregnancyPlus 数据不要求安装对应插件。菜单缩略图缺失单独显示为“不影响人物外观”的提示，不会将导出标为不完整；真正缺失的外观资源、已启用或无法确认的插件需求仍会报告。

每个角色包内有 `导出清单.txt`，输出位置另有总报告，均注明导出级别和未包含范围。“导出完成”表示**所选级别范围内**的文件已复制和校验；主动排除的高等级依赖不会导致“不完整”。所选范围内缺失、未知依赖、冲突或文件读取失败时继续复制其它文件，并显示“导出不完整”。取消会保留已完成的校验副本，清理未完成的临时文件，并在清单中标注未复制项。右键菜单和底部“更多”的“仅导出原始 PNG”快捷入口仍直接将 PNG 平铺到所选文件夹，不改变记住的导出级别。

移动、重命名、隔离也保留原始文件。隔离目录是游戏根目录下的 `.HS2ManagerTrash`，始终排除在扫描之外。左侧“可恢复隔离区”可恢复到原位置；若原名称已有文件，恢复时同样保留两份。

选中一张或多张卡片后，可点击底部“更多 → 永久删除…”、右键“永久删除…”或按 Shift+Delete。普通列表、“需要关注”和隔离区均支持。确认框列出数量、文件名与完整路径，默认取消；确认后永久删除选中的原始 PNG 及其收藏、标签、备注和封面缓存，**不经过回收站，无法恢复**。不会删除 MOD、插件、共享资源或其他同名卡。Delete 键仍为可恢复隔离。

删除时会重新核对文件版本；已变化、被占用或所在目录不可访问的项目保留记录并报告原因，其他项目继续处理。文件已缺失且父目录可正常读取时会清理残留记录。取消仅停止后续项目，已删除项目仍完成清理，结果显示完成、失败和未处理数量。中断恢复只补齐已删除文件的记录与缓存清理，不自动重新删除仍存在的文件；“文件已删除，待清理”表示原文件已经永久删除，可通过操作日志重试清理。

文件操作在 `Data\Operations` 中逐步记账。启动时自动检查未完成操作，“操作日志 → 恢复未完成操作”可再次检查。若跨盘移动中断而两端均有文件，程序保留两份并提示检查，不会擅自删除源文件。不要手动删改尚未恢复的操作记录。

NAS 离线时保留既有索引与封面；完整目录枚举失败时不会把全部人物卡标为已删除。确认目录在线后发现的缺失项会保留记录，方便检查。

## 3D 模型导出

人物列表可单张或批量“导出 3D 模型…”，预览工具栏和编辑页“更多”也提供入口。可选择通用 FBX、Blender 原生模型（`.blend`）或 Unreal 原生项目（`.uproject`）。编辑页包含点击时的未保存修改，并沿用当前服装与配饰范围；每个角色独立成包，附骨骼映射、报告和校验清单。

通用 FBX 包不含 Blender／Unreal Python 脚本。原生导出需在设置 → 模型导出选择本机软件，程序自动建立可编辑材质、打包贴图以及灯光、相机和调色场景，直接打开结果即可。保留参考姿态、原骨架、蒙皮和默认表情，不包含待机动画或物理模拟。跨引擎材质和后处理存在近似，具体差异与缺失列入报告；操作和实际验证范围见 [3D 模型导出说明](docs/MODEL-EXPORT.md)。

## 角色外观编辑

外部 AI 可以通过独立 C++ MCP 服务，根据参考图片创建人物卡，并调用素材检索、参数编辑、原生渲染以及贴图／配饰／发型／服装构建工具。解压后，把包根目录的 [AI-INSTALL.md](AI-INSTALL.md) 交给能操作本机文件的 AI，并说“请按这份文档安装 HS2 MCP 和技能”；AI 会识别实际路径、配置当前客户端、安装完整技能并验证连接。配置与实际验证边界见 [图片创建人物卡 Agent](docs/AI-CARD-AGENT.md)。

在人物详情、右键菜单或预览工具栏选择“编辑角色”，进入左侧分类、中央 3D、右侧参数的编辑页。可编辑脸部、身体、妆容、发型、服装和原版 20 槽配饰，素材选择支持原版/MOD 筛选、搜索、缩略图及当前项定位。Ctrl+Z/Ctrl+Y 撤销与重做；单项、分类及全部恢复均回到最近保存状态。

服装显示默认跟随游戏捏人规则：编辑身体时不穿衣物，编辑内衣、内裤、手套、连裤袜和袜子时显示内着，其余分类完整着装。预览工具栏的“显示”可手动选择完整着装、内着或不穿衣物，并单独隐藏配饰；选择“自动”恢复分类联动。这些设置仅影响预览，不修改服装数据，不计入撤销或保存。

Ctrl+S 默认在原目录另存“原文件名-编辑.png”，重名自动编号，并继承标签、备注、收藏和分类。“更多”提供其他目录、备份后覆盖及备份恢复。**原 PNG 封面始终逐字节保留**，不会随外观编辑更新。未保存离页会提示保存、放弃或取消，预览失败仍保留草稿。

C++ 版本已执行真实人物字段、无损读写、保存事务和界面流程检查，具体数量与样本见 [C++ 验证结果](docs/CPP-VALIDATION.md)。操作、保留规则与字段清单见 [角色编辑说明](docs/CHARACTER-EDITOR.md)；其中旧版游戏读取和画面对照记录保留为历史参考。

## 原生 GPU 3D 预览

“导入人物卡”旁的“临时预览”可打开一张 PNG 角色卡或一个 ZIP／7Z／RAR 压缩包，也可将文件拖入搜索栏下的专用区域。压缩包自动递归识别有效角色卡，按相对路径排序；多角色包默认展开侧栏。普通图片、服装卡及损坏卡会跳过，加密包支持输入密码、重试和取消。普通嵌套压缩包及分卷包需先自行解压。

临时预览使用已配置的游戏基础资源，优先读取角色所属目录的资源，其次为包内共享资源，再由本机补齐；包内 MOD 保持归档形式，插件 DLL 只读取元数据和资源。可调整镜头、灯光、播放状态并保存截图，编辑、模型导出及资料库管理操作不在临时模式中开放。“重新打开”可替换来源，Esc／返回恢复进入前的资料库筛选与选择。

角色快照、封面和派生缓存只存入实际本机数据目录的 `TemporaryPreview/<会话ID>`，不加入正式资料库、不更新正式 MOD 索引。返回、替换、取消、打开失败或退出时释放资源后清理，异常退出的遗留目录在下次启动时依据会话锁清理。程序附带从官方源码构建的 7-Zip 26.06 完整解码 DLL，无需安装解压软件；单文件上限 8 GiB、总解压上限 32 GiB、最多 100,000 个归档条目。

双击有效人物卡，或点击详情中的“打开 3D 预览”。GPU 在管理器进程内直接绘制到 WinUI `SwapChainPanel`，截图仅在保存时回读同一渲染结果。预览与编辑共用场景、原始几何、材质、动画和独立物理实现。无需启动游戏或 Studio。

本次 C++ 重写分别验证人物准备、GPU 画面、骨骼动态和界面交互，结果与复现入口见 [C++ 验证结果](docs/CPP-VALIDATION.md)。上一轮 [原生 GPU 迁移验收](docs/NATIVE-MIGRATION-RESULTS.md) 的 84 张卡及 360 帧数据属于历史 C# 实现，不能直接视为本次重写的通过结果。所有画面结论均限定于记录中的样本与资源配置。

| 保存截图 / Ctrl+S | 保存当前完成后处理的 GPU 画面 |
| Esc / 返回箭头 | 取消加载并释放当前人物 |

普通预览、临时预览与编辑预览均提供动作下拉框，按角色性别读取游戏与已安装 MOD 的捏人动作清单。切换动作保留镜头和暂停状态，从新动作的起始姿势开始；编辑外观参数时保留所选动作。动作选择仅影响预览，不写入角色卡。缺少动画片段或需要尚未支持的控制器状态映射的 MOD 动作会提示切换失败，并保留当前动作。远裁剪距离随镜头和人物范围调整，支持滚轮拉远到最大距离。

快速切卡和连续编辑仅提交最新加载与修订。加载时保持进度提示，镜头完成取景并提交完整首帧后才显示人物。隐藏视口停止绘制；缩放、DPI 变化和页面切换会更新视口。设备恢复从当前场景快照重建，失败时保留编辑草稿并提供重试；资源或效果诊断显示在预览提示中。不存在自动切回历史渲染器的入口。

原生资源缓存位于 `Data/NativeCpp`。数据库、设置、封面、备份及旧缓存保留，旧缓存不会作为新格式直接复用。首次解析本机游戏和 MOD 清单可能较慢，界面显示阶段进度。旧版依赖诊断中已存在的缺失资源继续报告，不会据此伪称资源齐全。

当前 C++ 模型加载已采用 NAS 资源包区间读取、名称索引及 LZMA 解压块复用；解压块在同会话和重启后均可复用。性能、缓存预算与内存测量见 [C++ 模型加载性能](docs/CPP-MODEL-LOADING-PERFORMANCE.md)。

预览完成加载后会释放原始读取器与内存解压块，保留场景需要的转换结果和轻量名称索引；当前读取器缓存目标为 128 MiB。最新内存对照与验证范围见 [角色卡预览内存优化](docs/PREVIEW-MEMORY.md)。

## MOD 诊断

读取已知 Sideloader 扩展引用，对照本地 `.zipmod` / `.zip` 的 `manifest.xml`，并识别已知迁移规则。详情中点击“更新”重建清单。

- **已找到**：上次扫描清单中存在对应 GUID，或通过已识别迁移映射满足。
- **缺失**：在完整扫描结果中没有该 GUID。
- **无法判断**：未建立索引、目录离线、清单损坏、未知扩展标识或无法确定的迁移规则。

这是静态诊断，不证明资源包内部每个贴图、物件或插件都可以正常加载，也不验证插件启用状态。安装或删除 MOD 后请更新索引。对无法识别的插件扩展保守显示“无法判断”。

## 源码构建

根目录命令入口只有 `start.cmd` 和 `push-releases.cmd`。本地构建与打包实现位于 `scripts`；桌面部署功能已移除。目录职责、中文注释要求、4 空格缩进规则与统一格式化命令见 [项目结构与代码规范](docs/DEVELOPMENT.md)。

正式构建需要 Windows x64、Visual Studio 2022 的桌面 C++ 工作负载、Windows SDK 和 CMake，无需 .NET SDK。脚本通过 Visual Studio Installer 定位工具，还原固定版本的 C++/WinRT 与 Windows App SDK 1.8。独立布料适配层使用 PhysX 3.4.2 源码；FBX 适配层使用 Autodesk FBX SDK 2020.3.7。首次构建缺少 SDK 时，通过 `scripts/build/Restore-NativeDependencies.ps1` 自动从 NVIDIA 和 Autodesk 官方地址恢复到 `.tools/ci`，校验固定的 PhysX 提交和 FBX 安装包 SHA-256；需要 Git for Windows、7-Zip 和网络连接，后续复用缓存。也可将按各自许可取得的 SDK 放入 `.tools/physx-3.4` 和 `.tools/fbx-native-2020.3.7`，或向 `scripts/package/Publish-Cpp.ps1` 传入 `-PhysXSource` / `-FbxSdkRoot` 指定外部目录。单独运行适配层构建脚本时，分别使用 `-Source` / `-SdkRoot`；显式路径错误会报出目录，不会自动替换。

```powershell
.\scripts\package\Publish-Cpp.ps1 -GamePath 'Z:\games\hs2\HS two DX - TSYMQ'
# 追加真实人物的场景、动态及 GPU 帧检查
.\scripts\package\Publish-Cpp.ps1 -GamePath 'Z:\games\hs2\HS two DX - TSYMQ' -PreviewTest
# 日常编译原生模块及 WinUI 界面，不生成便携 ZIP
.\scripts\build\Build-Cpp.ps1
```

`scripts/package/Publish-Cpp.ps1` 编译独立 FBX / 物理适配层、C++ 业务模块及 WinUI 程序，运行 CTest，发布自带 Windows App SDK 与 VC++ 运行库的便携目录及 ZIP，并写入 SHA-256 清单。构建和打包不再运行 GUI 窗口测试；需要时可单独执行 `tests/ui/Invoke-CppWinUiSmoke.ps1`。输出位于 `artifacts/release`；已有输出不会被覆盖，可用 `-OutputDirectory` 指定新目录。`-SkipTests` 跳过自动测试，发布包的纯原生依赖审计仍然执行。无需构建或下载 Unity。

各构建入口支持 `-Jobs 4` 控制编译、CTest、发布文件复制及 SHA-256 计算的并行度，默认最多 4 路；内存紧张时可指定 `-Jobs 1`。ZIP 使用快速压缩，文件内容保持一致，包体积可能略大。PhysX 兼容头文件仅在内容变化时更新，重复打包可复用已有编译结果。

`scripts/build/Build-Cpp.ps1` 默认使用增量构建。若 WinUI 的 PCH / PDB 缓存不一致导致 C2859 或 LNK1209，脚本会自动重建当前配置的 WinUI 项目并重试一次，保留已构建的 CMake 模块；重建失败或其他错误仍会终止构建。

PhysX 构建将编译器 PDB 放入各项目的中间目录，与链接器 PDB 分开，避免旧 SDK 共用调试数据库。遇到 LNK1318 等 PDB 缓存错误时，脚本会清理相关 Release 依赖并串行重建一次；其他错误或重试失败仍会终止发布。首次失败、清理和重建日志分别保存在 PhysX 构建目录的 `build-sdk.log`、`build-sdk-clean.log` 和 `build-sdk-rebuild.log` 中。

日常可双击 `start.cmd`，以 Release 配置构建并运行；首次使用会自动恢复缺失的 SDK 并构建原生适配层，无需预先打包。源码在 NAS 时，编译产物放在 `%LOCALAPPDATA%/HS2Manager/CppBuild/<项目标识>`，资料库保留原来的 `%LOCALAPPDATA%/HS2Manager/Source/<项目与配置标识>`，游戏资源仍可位于网络盘；映射盘和 UNC 路径复用已有资料库。`start.cmd --data "D:\HS2ManagerData"` 可指定本机资料。原有数据库、设置、封面、编辑备份及操作日志继续保留。

在 Visual Studio 打开 `HS2Manager.Native.sln` 或 `HS2Manager.slnx`。生产代码在 `src/HS2Manager.NativeApp`、`NativeCore`、`NativeScene`、`NativeRendering`、`NativeExport`、`NativeAssetBuild` 和 `NativeAgent`；底层库也可通过根目录 `CMakeLists.txt` 构建。旧 C#、Unity 与桥接源代码、参考解决方案及专用构建和测试脚本已移除，可通过 Git 历史查看。冻结数值基准保留在 `tests/fixtures`，供 C++ 回归检查及历史对照使用。

## 范围与兼容性

此版保留人物管理、角色外观编辑及原生 GPU 动态预览，编辑入口为已有男女角色卡，支持原版和本机已安装 MOD 素材。性别转换、游戏玩法属性、姿势编辑、插件专属面板与扩展配饰槽的专属编辑沿用原版范围；未知数据和扩展槽继续保留。本次迁移验证范围见 [C++ 验证结果](docs/CPP-VALIDATION.md)。Blender、Unreal 材质延续原有导出格式与转换行为，跨引擎画面仍有各自边界，见 [模型导出](docs/MODEL-EXPORT.md)。

若曾使用旧桥接版本，遗留桥接插件不会被新版启用；可在游戏退出后手动移除游戏 `BepInEx/plugins/HS2Manager` 子目录。程序没有安装系统服务或计划任务。
