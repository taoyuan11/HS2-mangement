# 图片创建 HS2 人物卡

使用调用方自身的视觉、绘图与建模能力决定角色外观，调用 HS2 MCP 执行实际操作。服务不包含模型 API，单次工具调用不会自行识图或自动计算相似度。目标是还原可见特征；颜色相同、素材能加载、配饰数量齐全都不能替代外观比较。

## 开始与迭代

1. 调用 `hs2_capabilities` 检查环境、目标性别基准卡和修正预算；`hs2_begin_card` 接收聊天附件的绝对路径或 MIME 与 Base64。目标性别无法判断时询问。基准卡仅作为起点，不能沿用其脸型、夸张比例或重妆而不比较。
2. 在 `analysis` 中记录脸型、眼鼻唇关系、发型轮廓、身材比例、服装剪裁与分层、标志性配饰和材质；区分可见、遮挡和补全。多视图图片按实际边界裁剪，不假设等宽三栏。用 `hs2_set_reference_regions` 标注可见视图及正侧脸，查看裁剪结果后再调整，格式见 [对照与评估](references/quality.md)。裁剪不会增加原图细节。
3. 调用 `hs2_get_schema` 读取真实字段与范围，使用原始数值，不能乘以 `display_scale`。先渲染基准版本，比较脸和身体。对不确定方向的滑条用 `hs2_probe_fields`；脸部默认正侧脸，身体默认正侧全身，返回负向／当前／正向对照图，不消耗修正。小范围调节，不凭字段编号猜语义。
4. 用 `hs2_search_assets` 检索并查看候选缩略图，以轮廓、分缝、长度、剪裁和透明材质选择素材；名称与颜色只是检索线索。分页查看，不能把未显示的缩略图当成已看过。传入返回的 `asset_id`，不要猜素材编号。先试穿少数候选，优先选择结构接近的成熟素材。
5. 使用 `hs2_apply_changes` 按主要差异分组修正。每轮先解决最影响辨识的脸型、眼睛比例、刘海／后发轮廓、身体或衣装轮廓，再处理珠宝、纹样。`hs2_render` 默认输出正侧背、正侧脸和左参考右渲染对照。比较后用 `hs2_review_render` 记录具体观察、待修项和下一步；`mark_best: true` 保存已看过的最佳版本。`hs2_apply_changes.mark_best` 只是候选，不能在看图前认定改好了。
6. 缺少素材时阅读 [素材制作接口](references/assets.md)。对已有素材的材质或花纹差异，先考虑贴图和参数；轮廓不匹配才制作网格。发片、布料、首饰需要不同几何和材质，简单平面、管线、球体的组装只能作为粗模。先看正侧背验证尺度和贴合，再增加细节。不要为了“做齐”细节耗尽脸和发型的修正预算。

耗时工具返回 `job_id`，查询直到 `completed`、`failed`、`cancelled` 或 `interrupted`。查看 `result` 中的图像和诊断；失败不表示草稿丢失。停止工作前取消仍运行的本任务作业。每次修改传最新 `expected_revision`，冲突时重读会话。新配置默认 24 轮，已有配置以 capabilities 为准；探测、裁剪、渲染、评估不消耗修改轮次，保留预算给看图后的纠正。每项素材保持相同 `asset_key`，最多三次，不通过改名绕过上限。连续修改无改善时回到最佳版本，改变素材或实现方式，不能只增加细节。

## 验证与交付

在最终版本上渲染所有已标注的参考视图及正侧背、正侧脸，用 `hs2_review_render` 逐项评估 face/hair/body/outfit/accessories/materials。原图可见而结果缺失的特征属于 `needs_work`，不能写成 `not_visible`。头饰过大、眼睛过大、硬板刘海、直筒裙摆或不透明薄纱等明显差异仍存在时继续修正；用户只要求草稿或达到预算时如实交付待修预览。动态和服装状态另行查看，不能代替完整穿着的静态验收。

逐项评估通过后调用 `hs2_validate`；技术检查通过再 `hs2_finalize_card`，提交 `visual_assessment: {"passed": true, "notes": "具体比较结论及保留差异"}`。单独的 passed 不能代替逐项评估。修改角色、更新裁剪或重新渲染后原评估失效。服务使用已评估的正面图作为封面，输出独立角色包与对照图。失败时保留草稿并报告具体缺项及最佳版本。

交付时提供角色包目录、预览、生成报告和缺项。明确区分结构、依赖、原生渲染、视觉评估与真实 HS2 验证；未运行的游戏验证保持 `not_run`。单张图未展示的部位列为补全，不编造相似度分数。
