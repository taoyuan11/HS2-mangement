# 图片创建 HS2 人物卡

使用调用方自身的视觉、绘图与建模能力决定角色外观，调用 HS2 MCP 执行实际操作。服务不包含模型 API，单次工具调用不会自行识图或自动计算相似度。目标是还原可见特征；颜色相同、素材能加载、配饰数量齐全都不能替代外观比较。

## 开始与迭代

1. 调用 `hs2_capabilities` 检查环境和目标性别基准卡；`max_iterations`、`max_asset_attempts` 为 null 表示无限。`hs2_begin_card` 接收聊天附件的绝对路径或 MIME 与 Base64。目标性别无法判断时询问。基准卡仅作为起点，不能沿用其脸型、夸张比例或重妆而不比较。
2. 在 `analysis` 中记录脸型、眼鼻唇关系、发型轮廓、身材比例、服装剪裁与分层、标志性配饰和材质；区分可见、遮挡和补全。多视图图片按实际边界裁剪，不假设等宽三栏。用 `hs2_set_reference_regions` 标注可见视图及正侧脸，查看裁剪结果后再调整，格式见 [对照与评估](references/quality.md)。裁剪不会增加原图细节。
3. 调用 `hs2_get_schema` 读取真实字段与范围，使用原始数值，不能乘以 `display_scale`。先渲染基准版本，比较脸和身体。对不确定方向的滑条用 `hs2_probe_fields`；脸部默认正侧脸，身体默认正侧全身，返回负向／当前／正向对照图，不消耗修正。小范围调节，不凭字段编号猜语义。
4. 所有需要的外观素材直接新建，不搜索或试穿现成替代品。`hs2_search_assets` 已停用。读取 Schema 字段的 `creation`，以 `target_path` 调用 `hs2_prepare_asset`，按 [素材制作接口](references/assets.md) 制作发型、服装、配饰、头部、皮肤、虹膜、妆容、花纹与布局。游戏基础人体、骨架、Shader、组件只作为兼容底座。技术模板由服务自动解析，不猜素材编号。
5. 使用 `hs2_apply_changes` 按主要差异分组修正。每轮先解决最影响辨识的脸型、眼睛比例、刘海／后发轮廓、身体或衣装轮廓，再处理珠宝、纹样。`hs2_render` 默认输出正侧背、正侧脸和左参考右渲染对照。比较后用 `hs2_review_render` 记录具体观察、待修项和下一步；`mark_best: true` 保存已看过的最佳版本。`hs2_apply_changes.mark_best` 只是候选，不能在看图前认定改好了。
6. 发片、布料、首饰需要不同几何和材质，简单平面、管线、球体的组装只能作为粗模。先看正侧背验证尺度和贴合，再制作纹样和细节。头部必须使用准备接口返回的中性绑定参考，保持拓扑与表情数据；不要拿已变形预览网格覆盖头部。

耗时工具返回 `job_id`，查询直到 `completed`、`failed`、`cancelled` 或 `interrupted`。每次修改传最新 `expected_revision`，冲突时重读会话。同一素材持续使用相同 `asset_key`，角色修改和素材构建都无次数上限。失败后按诊断修正输入；连续修改无改善时回到已评估的最佳版本，改变几何、贴图或实现方式，不能原样重复失败操作或只增加细节。记录待修动作并持续执行，直到完整验收通过。用户停止、连接中断或缺少无法自行补齐的依赖时保留会话、最佳版本与待修项，恢复后继续；不得把中断称为完成。停止前取消本任务仍运行的作业。

## 验证与交付

在最终版本上渲染所有已标注的参考视图及正侧背、正侧脸，用 `hs2_review_render` 逐项评估 face/hair/body/outfit/accessories/materials。原图可见而结果缺失的特征属于 `needs_work`，不能写成 `not_visible`。头饰过大、眼睛过大、硬板刘海、直筒裙摆或不透明薄纱等明显差异仍存在时继续修正。动态和服装状态另行查看，不能代替完整穿着的静态验收。

逐项评估通过后调用 `hs2_validate`，处理 `creation_issues` 中尚未新建的启用素材，以及结构、依赖和渲染问题，再 `hs2_finalize_card`。提交 `visual_assessment: {"passed": true, "notes": "具体比较结论及保留差异"}`；单独的 passed 不能代替逐项评估。修改角色、更新裁剪或重新渲染后原评估失效。返回 `needs_work` 就继续修正，只有 `status: complete` 才完成交付。服务使用已评估的正面图作为封面，输出独立角色包与对照图。

交付时提供角色包目录、预览、生成报告和缺项。明确区分结构、依赖、原生渲染、视觉评估与真实 HS2 验证；未运行的游戏验证保持 `not_run`。单张图未展示的部位列为补全，不编造相似度分数。
