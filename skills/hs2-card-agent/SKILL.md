# 图片创建 HS2 人物卡

使用调用方自身的视觉、绘图与建模能力决定角色外观，调用 HS2 MCP 执行实际操作。服务不包含模型 API，单次工具调用不会自行识图。

## 开始与迭代

1. 调用 `hs2_capabilities` 检查游戏和目标性别基准卡。传入聊天附件的本地绝对路径，或 MIME 与 Base64，调用 `hs2_begin_card`。选择目标男女模板；目标无法判断时向用户询问。
2. 在 `analysis` 中记录目标特征、可见区域、遮挡和补全部分。调用 `hs2_get_schema` 读取真实字段与范围。数值是原始数值，不是乘以 `display_scale` 后的 UI 数值。
3. 用 `hs2_search_assets` 检索发型、皮肤、妆容、服装与配饰。查看缩略图后选择，传入返回的 `asset_id`，不要猜测游戏素材编号。
4. 使用 `hs2_apply_changes` 按脸型、五官、颜色、身体、发型和服装分组调整。每次修改传入最新 `expected_revision`；发生冲突时重新读取会话。合理合并修改以控制默认十二轮预算。满意的中间结果传 `mark_best: true`。
5. 用 `hs2_render` 获取正面、侧面、背面、面部或三分之四视图。先对齐参考角度与取景，再比较特征。需要了解滑条方向时用 `hs2_probe_fields`，它不修改草稿。
6. 缺少素材时阅读 [素材制作接口](references/assets.md)。贴图、配饰、发型和服装均可创建；内容由调用方的绘图工具或 Blender Python 脚本制作，HS2 工具执行适配和验证。

耗时工具返回 `job_id`。调用 `hs2_get_job` 直到 `completed`、`failed`、`cancelled` 或 `interrupted`。查看 `result` 中的图像和诊断；任务失败不表示已有草稿丢失。停止工作前取消仍运行的本任务作业。每项素材的 `asset_key` 应在修正尝试中保持不变，默认最多三次，不通过换标识绕过上限。

## 验证与交付

在最终版本上渲染，然后调用 `hs2_validate`。人工视觉评估应覆盖相似程度、身体与衣着比例、穿插、材质、背面补全；有动态或服装状态时查看相应结果。

通过后调用 `hs2_finalize_card`，提交 `visual_assessment: {"passed": true, "notes": "具体比较结论及保留差异"}`。服务会生成新封面和姓名并输出独立角色包。失败项保留草稿，报告具体缺项与最佳版本，不将“打包成功”表述成“外观还原完成”。

交付时提供角色包目录、预览、生成报告和缺项。明确区分结构、依赖、原生渲染、视觉评估与真实 HS2 验证；未运行的游戏验证保持 `not_run`。单张图未展示的部位列为补全，不编造相似度分数。
